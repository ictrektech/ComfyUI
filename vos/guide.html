ComfyUI · 使用与 API 集成

在 VOS 中选择 应用抽屉 → ComfyUI → 工作流编辑器。应用使用 VOS 登录，编辑器语言跟随 VOS。首次打开时会为当前账户启动工作进程；如果计算资源已满，等待其他账户结束运行后重试。工作流、输入、设置和输出按账户保存；队列及运行历史随工作进程结束清空。

使用共享模型

  1. 安装 V-Scheduler 和 ComfyUI，为两者选择同一个 NAS 共享模型目录。根据设备选择 CPU 或 CUDA profile；大型工作流通常需要 GPU。
  2. 在 V-Scheduler 的模型管理中下载兼容的 Hugging Face 或 ModelScope 权重，等待状态为“就绪”。支持原生 ComfyUI 分类目录（例如 checkpoints/、split_files/diffusion_models/、loras/）里的 .safetensors，以及可识别的单文件权重。
  3. 约 30 秒后刷新编辑器的模型列表，以来源、仓库和文件名识别模型，选择相应节点的加载器，连接工作流并点击运行。如果未出现，检查路径是否一致、模型是否就绪，以及权重是否适用于该加载器。

共享模型只读，不需要再次下载。Ollama blob、分片 Diffusers 权重和 V-Scheduler 网关远程模型不属于共享权重，第三方自定义节点未启用。

使用 Comfy 云节点

本地工作流只需 VOS 账号。在编辑器的节点库中添加 Comfy 合作伙伴节点，连接输入与输出，再运行工作流。使用云节点时，点击右上角头像登录 Comfy 官方账号。VOS 的局域网地址或未列入 Comfy 白名单的域名请选择 Comfy API 密钥，输入自己的 Comfy 账号密钥。设备和浏览器需要能连接 Comfy 服务，账号需要有可用积分。云节点会将该节点的输入发送给服务提供方。遇到未登录提示时，完成认证后重新运行；若凭据被拒绝，检查密钥和积分。

API 集成

通过 VOS HTTPS 访问 /app/com.ictrek.comfyui/editor/api。API 调用使用通过本应用 OAuth2 客户端（com.ictrek.comfyui，授权码与 PKCE）取得的 VOS 用户 access token：Authorization: Bearer <token>。编辑器使用同域 HttpOnly 会话。应用身份 token 和其他客户端的 token 不可使用。请求仅在令牌持有者的工作区执行；JSON 请求需设置 Content-Type: application/json，图片上传用 multipart。

  • GET /models 返回分类字符串数组；GET /models/{folder} 返回某一分类的文件名数组（未准备模型时可为空）；GET /object_info/{node_class} 可查看相应节点的输入约束。
  • POST /prompt 提交 API 格式工作流。prompt 为以节点 ID 为键的对象；值含 class_type 和 inputs，输入连线是 [节点ID, 输出口索引]。成功返回 prompt_id、队列序号 number 和 node_errors。校验错误返回 400 和节点错误详情。
  • 云节点的 GET /object_info/{node_class} 响应含 api_node: true。通过 API 运行云节点时，仍须使用上文的 VOS 请求头，并在 POST /prompt 的可选对象 extra_data 中传入 api_key_comfy_org（Comfy 账号密钥字符串）或 auth_token_comfy_org（Comfy Partner Node 令牌字符串）。两者都有值时优先使用令牌。缺省、空串或 null 视为未提供。官方服务认证失败可在 GET /history/{prompt_id} 的 status.messages 中看到 execution_error，应核对凭据后重新提交。
  • GET /history/{prompt_id} 在记录可用时返回以 ID 为键的 JSON 对象，含 status 和 outputs。执行中可能返回 {}。使用 GET /view?filename=…&subfolder=…&type=output 下载二进制产物。
  • WebSocket 使用 wss://<device>/app/com.ictrek.comfyui/editor/ws，可用 clientId 对应提交请求中的 client_id。状态、进度和错误使用 {type,data}，预览可为二进制。重连后可用历史查询确认任务状态。
  • 401：重新登录或更换已过期令牌。403：使用同域页面或按上文使用正确凭据。404：检查路径或文件名。502：工作进程断开；先查任务历史再决定重提。503：VOS 身份服务未就绪、工作进程未启动或工作区已满；有 Retry-After 时按该值等待。提交不是幂等操作，超时后先查队列。

ComfyUI · User and API Guide

Open App Drawer → ComfyUI → Workflow Editor. The editor uses VOS sign-in and follows the VOS language. Opening it starts a worker for your account. If the worker slots are busy, wait for a slot and try again. Workflows, inputs, settings and outputs persist by account; the queue and run history clear when the worker stops.

Use a shared model

  1. Install V-Scheduler and ComfyUI and choose the same NAS shared model directory in both apps. Choose a CPU or CUDA profile for the device; large workflows generally require a GPU.
  2. Download compatible Hugging Face or ModelScope weights in the V-Scheduler model manager and wait for Ready. Use .safetensors weights in native ComfyUI folders such as checkpoints/, split_files/diffusion_models/, or loras/. Recognizable standalone files are also supported.
  3. After about 30 seconds, refresh the model list in the editor. Identify the weights by source, repository and filename, select them in the matching loader, connect the workflow and click Run. If the model does not appear, check the shared path, download state and loader compatibility.

The shared model directory is read-only, with no second download. Ollama blobs, sharded Diffusers files and V-Scheduler gateway models are outside shared weight discovery. Third-party custom nodes are disabled.

Use Comfy cloud nodes

Local workflows require only your VOS account. Add a Comfy Partner Node from the editor's node library, connect its inputs and outputs, and run the workflow. For cloud nodes, open the profile menu and sign in to your official Comfy account. On a LAN address or a domain outside Comfy's allowlist, choose Comfy API Key and enter your Comfy account key. The browser and device must be able to reach Comfy services, and your account needs available credits. A cloud node sends its inputs to the provider. If prompted to sign in, authenticate and run again; if a credential is rejected, check the key and credits.

API integration

Use the VOS HTTPS origin and /app/com.ictrek.comfyui/editor/api. API clients use a VOS user access token issued to the com.ictrek.comfyui OAuth2 client (authorization code with PKCE): Authorization: Bearer <token>. The editor uses a same-origin HttpOnly session. App-context tokens and tokens issued to other clients are rejected. Each request uses the token holder’s workspace. Send JSON with Content-Type: application/json; use multipart for image uploads.

  • GET /models returns an array of categories; GET /models/{folder} returns filenames for that category, or an empty array if no weights are ready. GET /object_info/{node_class} exposes that node’s input schema.
  • POST /prompt submits an API-format workflow. prompt maps node IDs to objects with class_type and inputs. A link is [node ID, output index]. A successful submission returns prompt_id, queue number and node_errors. Validation errors return 400 and node details.
  • GET /object_info/{node_class} reports api_node: true for cloud nodes. To run one through the API, keep the VOS authorization header above and send api_key_comfy_org (a Comfy account key string) or auth_token_comfy_org (a Comfy Partner Node token string) in the optional extra_data object of POST /prompt. A nonempty token takes precedence. Omitted, null, and empty string values are treated as absent. If the service rejects authentication, look for execution_error in status.messages from GET /history/{prompt_id}. Check the credential before resubmitting.
  • GET /history/{prompt_id} returns a JSON object keyed by the ID, with status and outputs when available. It can return {} while the workflow runs. Download binary outputs via GET /view?filename=…&subfolder=…&type=output.
  • Connect to wss://<device>/app/com.ictrek.comfyui/editor/ws with a clientId matching the prompt request’s client_id. Status, progress and errors use {type,data} messages; previews may be binary. After reconnecting, check history for the result.
  • 401: sign in again or replace the expired token. 403: use the same-origin editor or the credentials described above. 404: check the path or filename. 502: worker disconnected; check job history before retrying. 503: VOS authentication unavailable, startup incomplete, or worker slots busy; honor Retry-After when present. Submission is not idempotent; check the queue before retrying a timed-out submission.
